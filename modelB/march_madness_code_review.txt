================================================================================
MARCH MADNESS PREDICTION CODE REVIEW
Comparative analysis of 10 notebooks (Python + R) and 1 results workbook
================================================================================

SCOPE & METHOD
--------------
This review covers the files under /tmp/inputs/. Each notebook is given its own
section describing: purpose / target tournament year, Python (or R) tech stack,
data acquisition, preprocessing, modeling techniques, prediction on unknown
(future) brackets, output files, and visualizations. A COMPARATIVE SECTION at
the end contrasts how the files perform the same tasks differently and notes
where one file is an extension of another.

Notes on conventions observed across the project:
  * "win" / "win_team1" / "team1_win" = 1 means team1 beat team2.
  * Many notebooks build a per-matchup row by joining season team stats onto
    team1 and team2 (suffixes _team1 / _team2).
  * Reported below are PREDICTIONS on future brackets (these are requested).
    Training/validation performance numbers printed in cells are NOT reported,
    because they reflect whatever hyperparameters were last run.
  * Where a displayed table is clearly stale (inconsistent with the data the
    cell loads), that is flagged rather than interpreted.

FILE INVENTORY (grouped by role)
  Data scrapers / feature builders:
    - SRS and SOS pray for me.ipynb   (opponent-adjusted ratings via linear algebra)
    - march26_scrape.ipynb            (2026 team stats + bracket + historical results)
    - march_epilogue.ipynb            (2010-2026 team-season dataset, leakage-aware)
  Modeling / prediction notebooks:
    - march.ipynb                     (2024 + 2025; large, many sklearn models)
    - march epilogue training.ipynb   (builds 2010-26 matchup DB; trains RandomForest)
    - march2.ipynb                    (2025 "practice"; NN + trees + weighted vote + MC sim)
    - march2.1.ipynb                  (2026; full model zoo, PCA track, calibration, MC sim)
    - march2.11.ipynb                 (condensed PCA pipeline; simulates 2025 AND 2026)
    - predicting26.ipynb              (2026 final predictions from saved models + MC sim)
  Exploratory (R):
    - march.Rmd                       (2024 four-factors EDA + stepwise GLM on 2023 data)
  Results artifact:
    - prediction_results.xlsx         (consolidated/scored 2025 & 2026 predictions)

A high-level dependency chain emerges (details in each section and in the
comparison):
  SRS/SOS ratings + scrapers  ->  season/matchup databases  ->
  training notebooks (save models)  ->  predicting26 / march2.* (load models,
  simulate bracket)  ->  prediction_results.xlsx (human-readable scorecard).

# FILE: march.Rmd   (R Markdown)  --  TARGET: 2024 tournament
################################################################################

PURPOSE
  Exploratory analysis of the 2024 field and a stepwise logistic/linear model,
  FIT ON 2023 ("last year") data, to study which team-season statistics relate
  to deep tournament runs. Header: author "Josh LaFronz", date 2024-03-17.

TECH STACK (R)
  tidyverse (dplyr, tidyr, stringr, ggplot2), scales, ggthemes, ggrepel,
  lubridate; modeling: MASS, leaps, car (VIF), olsrr (Mallows' Cp).

DATA ACQUISITION / PREPROCESSING
  * Reads local CSVs exported from sports-reference-style tables: basic_off,
    basic_def, advanced_off, advanced_def (for 2024 and, later, a "march 23"
    folder for 2023).
  * Hardcodes the 2024 field: tourney_teams, first_four, conference, seeds;
    builds `field_of_68` data frame; manually removes First-Four losers.
  * Heavy column renaming (disambiguating duplicated W/L columns), drops index
    columns, merges offense/defense and basic/advanced into one `final_table`.
  * Hardcodes round-by-round survivors (r1_winners ... r4_winners, and for the
    2023 build: r_32, s_16, e_8, final_4, final, winner) and turns them into
    binary outcome columns (r_32, s_16, e_8, final_4, final, winner).

MODELING TECHNIQUES
  * Target modeled: `final` (reached the championship game), built on the 2023
    table. glm() is called WITHOUT family=binomial, i.e. a Gaussian/linear
    probability model on a 0/1 response (not a true logistic fit).
  * Variable selection: step() forward and backward selection by F-test between
    a null model and a full model containing ~70 predictors.
  * Model diagnostics helper glm_eval(): summary(), extractAIC(), car::vif(),
    olsrr::ols_mallows_cp() -- manual multicollinearity / Cp pruning.
  * A true_shooting() utility function is defined.

PREDICTION ON UNKNOWN DATA
  * None produced. There is no predict() on the 2024 field; the GLM work is
    inferential / feature-selection oriented, not a bracket forecast.

OUTPUTS
  * No files written. Output is inline tables and figures only.

VISUALIZATIONS (designed figures, not raw output)
  * Extensive four-factors EDA with ggplot2: boxplots/scatter of 3P rate vs 3P%,
    FT rate vs FT%; faceted-by-region scatter/line plots of eFG%, FT/FGA,
    TOV%, ORB% colored by matchup/seed, point size by ORtg/DRtg, shape by
    higher_seed; AdjEM vs net rating colored by power-conference flag.

# FILE: SRS and SOS pray for me.ipynb   --  ratings builder (multi-season)
################################################################################

PURPOSE
  Scrape college-basketball schedules and compute opponent-adjusted ratings
  (SRS = Simple Rating System, SOS = Strength of Schedule) by solving a linear
  system. This is a FEATURE-ENGINEERING utility, not a predictor.

TECH STACK (Python)
  cloudscraper + urllib3 + requests (HTTP), BeautifulSoup/bs4 (+ Comment, Tag)
  for parsing, pandas, numpy, scipy (scipy.linalg and scipy.sparse for the
  solve), matplotlib, google.colab.files for downloads.

DATA ACQUISITION
  * Helper soupify_with_cloudscraper() to bypass anti-scraping; helpers to list
    table ids and header columns.
  * Iterates seasons (a loop over 2022-2026 is shown) pulling each team's
    schedule page; records opponents and point differential per game, keeping
    only game_type in {REG, CTOURN} -- i.e. regular season + conference
    tournaments, DELIBERATELY EXCLUDING NCAA-tournament games (important for
    avoiding target leakage downstream). Writes one schedule CSV per year.

PREPROCESSING / RATINGS MATH
  * MoV (mean margin of victory) per team.
  * Builds matrix M (teams x teams): diagonal = -1, each opponent entry += 1/n;
    last row set to 1 as the sum-to-zero normalization. Right-hand side A = -MoV
    (last entry 0). Solves M r = A with scipy.sparse.linalg.spsolve for team
    ratings. SOS = mean of opponents' ratings; SRS = SOS + MoV.
  * An alternate vectorized SOS ("from gemini" cell): zero the diagonal and
    matrix-multiply the averaging matrix by the ratings vector.
  * Manual alias fixes (e.g. "SIU Edwardsville" -> "Southern Illinois-
    Edwardsville", "VMI" -> "Virginia Military Institute").
  * A "Looping" section reloads the saved schedule CSVs and recomputes ratings
    per season into a tidy frame (year, team, games, MoV, SOS, SRS).
  * An "Iterative method" section is present but scratch/incomplete.

MODELING TECHNIQUES
  * None (no classifier/regressor). Pure linear-algebra rating computation.

PREDICTION ON UNKNOWN DATA
  * None. It sorts/displays top teams per year by SRS for inspection only.

OUTPUTS (CSV)
  * schedule{YY}DF.csv, scheduleDF.csv, scheduleDf26.csv (raw schedules),
    ncaa_srs_sos_1015.csv (2010-2015 ratings), SRS_SOS_fixed.csv
    (consolidated ratings -- consumed by march_epilogue.ipynb).

PREDICTION ON UNKNOWN DATA

OUTPUTS (CSV)

VISUALIZATIONS

    threshold, with dashed 2.5%/97.5% significance lines and the 2026 rate
    overlaid (matplotlib).

PURPOSE

  independently computed SRS/SOS ratings while explicitly guarding against
  target leakage (variable/file names use "leak" / "no_leakage").

  cloudscraper, urllib3, requests, BeautifulSoup (+ Comment, Tag), pandas,
  numpy, matplotlib, google.colab.files.

    URLs to "-gamelogs"). Builds d1 (Division-I) team-stat tables per year and

PURPOSE
  End-to-end pipeline: scrape season/team stats and brackets, build matchup
  databases, train many classifiers ROUND-BY-ROUND, then predict a bracket
  region-by-region / round-by-round. Round-model development is oriented to

  (Regressor), LogisticRegression, SGDClassifier, SVC/LinearSVC, VotingClassifier,
  StackingClassifier, PCA, StandardScaler, make_pipeline, train_test_split,
  RandomizedSearchCV; metrics recall/f1/precision/roc_auc.

DATA ACQUISITION / PREPROCESSING
  * Scrapes matchups and team totals (team + opponent rows) via playwright;
    computes possessions, off_rtg/def_rtg/net_rtg, pace, and keeps selected
    percentage columns. Builds database.csv, database2.csv and the 2025
    database25.csv by joining team stats onto team1/team2.
  * Two feature philosophies appear: (a) raw team1/team2 side-by-side stats, and

  * Evaluation via accuracy/.score plus roc_auc/precision/recall/f1 in spots.

PREDICTION ON UNKNOWN DATA (2025 bracket; team1_win=1 means team1 advances)

OUTPUTS (CSV)

VISUALIZATIONS

# FILE: march2.ipynb   --  TARGET: 2025 ("for practice")
################################################################################

PURPOSE
  A cleaner modeling redo: neural network + tree ensemble with a weighted soft
  vote, plus a Monte Carlo bracket simulation, demonstrated on 2025.

TECH STACK (Python)
  torch (custom nn.Module, DataLoader), torchviz (make_dot); scikit-learn
  (StandardScaler, train_test_split, DecisionTree, RandomForest, AdaBoost,
  VotingClassifier, calibration_curve, roc_curve/auc/roc_auc_score, log_loss);
  xgboost (XGBClassifier); scipy.optimize.minimize; pandas, numpy, matplotlib,
  pickle; playwright imported for scraping.

DATA ACQUISITION / PREPROCESSING
  * Loads database2.csv + database25.csv (historical + 2025).
  * DIFFERENCE features: keeps seed/SRS/SOS/off_rtg/def_rtg/pace/eFG/ORB_pct/
    TOV_pct/FT_FGA/3PAr, forms team1-minus-team2 diffs plus net_eFG and
    net_TOV_pct, and applies MIRRORED augmentation (each game duplicated negated
    with label y -> 1-y). StandardScaler fitted and pickled (standard_scaler.pkl).

MODELING TECHNIQUES
  * Neural net: Model(nn.Module) with an input Linear(->32), a ModuleList of
    hidden 32->32 layers, ReLU and Sigmoid; trained with a manual epoch loop and
    a custom batch DataLoader; train/test loss curves tracked.
  * Tree/boosting models: RandomForest, AdaBoost, XGBoost (plus a looping XGB
    search). Models pickled (random_forest_model.pkl, ada_boost_model.pkl,
    XGBoost_model.pkl).
  * ENSEMBLE = weighted soft vote of NN + AdaBoost + XGB + RandomForest
    probabilities. Weight search EVOLVES through three methods: (1) a small
    hand-listed grid of weight tuples; (2) random Dirichlet sampling of 500
    weight vectors with a ROC/Youden-J threshold; (3) scipy.optimize.minimize
    (SLSQP) minimizing validation log_loss over the weights (most principled).
  * A "Data Process with a Valid Set" section separates train/test/valid and
    notes a fix to reuse the SAME fitted scaler across splits (leakage fix).
  * Predictions are symmetrized: each matchup is scored in both team orderings
    and averaged.

PREDICTION ON UNKNOWN DATA (2025)
  * Applies the weighted ensemble to the 2025 bracket and advances winners round
    by round (deterministic fill), then runs a MONTE CARLO simulation: a Bracket
    class stores rounds; MC_MM() samples each game from predicted probabilities;
    10,000 simulated tournaments are aggregated in a `finishes` table counting
    how often each team reaches each round (64/32/16/8/4/2/1), from which
    round-advancement probabilities are computed. Most-frequent deep-run teams
    include Auburn, Duke, Florida, Houston (top seeds); most-common bracket
    "signatures" are tallied with collections.Counter.

OUTPUTS
  * Models: random_forest_model.pkl, ada_boost_model.pkl, XGBoost_model.pkl,
    standard_scaler.pkl, torch mod11.pth and mod13v2.pth.
  * CSV: finishes.csv, finishes50k.csv (simulation finish counts).

VISUALIZATIONS
  * Training/Test loss curves; ROC curves; a calibration/reliability diagram;
    and a torchviz make_dot computation-graph drawing of the neural net.

  * CALIBRATION: reliability diagrams (calibration_curve, n_bins=10) for the NN,

  * ENSEMBLE weights via scipy.optimize.minimize on validation log_loss, for

# FILE: march2.11.ipynb   --  condensed PCA pipeline; simulates 2025 AND 2026
################################################################################

PURPOSE
  A trimmed, cleaner version of the march2.1 workflow focused on a PCA-based
  ensemble, used to simulate both the 2025 and 2026 brackets.

TECH STACK (Python)
  torch + skorch (NeuralNetClassifier, EarlyStopping, ValidSplit); scikit-learn
  (AdaBoost/RandomForest/GradientBoosting/Bagging, LogisticRegressionCV,
  SGDClassifier, SVC, DecisionTree, PCA, StandardScaler, Pipeline,
  GridSearchCV/RandomizedSearchCV, log_loss/accuracy/precision, roc/auc);
  xgboost; scipy.optimize.minimize, scipy.stats (loguniform, uniform); plotnine;
  pandas/numpy/matplotlib; pickle; google.colab.files.

DATA ACQUISITION / PREPROCESSING
  * Trains on database2.csv + database25.csv; same difference-feature + mirrored
    augmentation design.
  * PCA dimensionality chosen from a SCREE/variance analysis: cumulative
    explained-variance is computed for every component count and n_components=9
    is selected (~>=95% variance). Fitted StandardScaler+PCA pickled.

MODELING TECHNIQUES
  * Retrains the model set in 9-component PCA space and saves them
    (<model>_9_pca.pkl, log_9_pca.pkl, nn_9_pca.pkl); loads the full set
    (nn, rf, ada, xgb, pca, sgd, svc, bag, gb, log) for ensembling.
  * Ensemble weighting via scipy.optimize.minimize (log_loss), consistent with
    the march2 family.

PREDICTION ON UNKNOWN DATA (both years)

0) LINEAGE / WHICH FILES EXTEND WHICH
   * The project splits into an ORIGINAL line (march.Rmd + march.ipynb) and a
     REFACTORED "epilogue/march2" line that is cleaner and leakage-aware.
   * march.Rmd (R, 2024) and march.ipynb (Python, 2024->2025) are parallel 2024
     efforts; march.ipynb is the productionized successor (actual bracket
     forecasts vs the Rmd's inference/EDA).
   * march2.ipynb extends march.ipynb: same database*.csv inputs but adds a
     neural net, mirrored augmentation, weighted-vote ensemble, and Monte Carlo.
   * march2.1.ipynb is a strict superset of march2.ipynb (adds skorch, nested CV,
     a full pickled model zoo, a PCA track, VIF, and calibration) targeting 2026.
   * march2.11.ipynb is a condensed extension of march2.1 centered on a 9-
     component PCA ensemble, reused for BOTH 2025 and 2026.
   * march_epilogue.ipynb (data) + "march epilogue training.ipynb" (DB + RF) are
     a cleaner rebuild of march.ipynb's scraping/DB steps with explicit leakage
     control; "SRS and SOS pray for me.ipynb" supplies their ratings and
     march26_scrape.ipynb supplies the 2026 inputs.
   * predicting26.ipynb is the inference-only endpoint that consumes the saved
     13-feature model set; prediction_results.xlsx is the endpoint scorecard.

1) ACQUIRING DATA
   * Scraper stack differs: march.ipynb and march2.ipynb use PLAYWRIGHT
     (headless browser); SRS/epilogue use CLOUDSCRAPER+urllib3; march26_scrape
     uses plain urllib3/requests. All parse with BeautifulSoup.
   * Ratings: "SRS and SOS pray for me.ipynb" computes SRS/SOS from first
     principles by solving a sparse linear system (regular + conf-tourney games
     only). march26_scrape instead takes SRS/SOS straight from the stats page.
     march.ipynb relies on raw box-score-derived stats and does not recompute
     opponent-adjusted SRS the same way.
   * Season coverage: march.Rmd = 2024 (trained on 2023); march.ipynb = through
     2024/2025; the epilogue/march2 line assembles 2010-2026 (skipping 2020).
   * LEAKAGE AWARENESS is the clearest data-quality improvement: the epilogue
     files deliberately exclude NCAA-tournament games from the ratings and build
     no_leakage.csv / df_noLeaks_10-26.csv, whereas march.ipynb / march.Rmd show
     no explicit guard against tournament-outcome leakage into features.

2) FEATURE REPRESENTATION
   * march.Rmd: raw team-season columns as GLM predictors (plus four-factors).
   * march.ipynb: primarily raw team1/team2 side-by-side stats, with a later
     "diff dataset" experiment and DecisionTree-importance feature pruning.
   * Entire march2/epilogue line standardizes on DIFFERENCE features
     (team1 - team2) + a couple of net cross-terms, and MIRRORED augmentation
     (duplicate each game negated with flipped label) to enforce antisymmetry --
     a cleaner, better-posed formulation than raw side-by-side columns.
   * march2.1 / march2.11 add a PCA representation (12 and 9 components
     respectively) and multicollinearity screening (VIF), absent elsewhere.

3) TRAINING MODELS
   * march.Rmd: stepwise (forward/backward, F-test) variable selection with
     AIC/VIF/Mallows-Cp -- an inferential workflow, no resampling/CV.
   * march.ipynb: the widest set of base learners but tuned largely by MANUAL
     nested loops that select on the TEST set (see weakness note #6); separate
     models per tournament round.
   * "march epilogue training.ipynb": a single RandomForest with RandomizedSearchCV
     (neg_log_loss) on the mirrored diff data -- one model for all rounds.
   * march2.ipynb: manual torch NN + RF/AdaBoost/XGB, combined by a weighted soft
     vote whose weights progress from a hand grid -> Dirichlet sampling ->
     SLSQP log-loss optimization.
   * march2.1.ipynb: the most rigorous -- skorch NN with EarlyStopping +
     ValidSplit, RandomizedSearchCV across a 9-model dictionary (neg_log_loss),
     saved hyperparameters, calibration, and both raw and PCA pipelines.
   * march2.11.ipynb: same tooling but narrowed to the 9-component PCA ensemble.
   * Resampling spectrum, weakest -> strongest: none (Rmd) < single
     train/test with manual test-set tuning (march.ipynb) < single
     RandomizedSearchCV (epilogue training) < CV search + early stopping +
     calibration across many models (march2.1 / march2.11).

4) MODEL SELECTION / ENSEMBLING
   * march.ipynb: per-round VotingClassifier / StackingClassifier chosen by
     accuracy.
   * march2.*: a single cross-round probabilistic ensemble with log-loss-
     optimized weights; march2.1/march2.11 additionally calibrate probabilities
     and compare PCA vs non-PCA and "old (improperly trained)" vs "new (no
     leakage)" model sets -- an explicit acknowledgement and correction of an
     earlier training error.

5) MAKING PREDICTIONS
   * DETERMINISTIC round-by-round (pick the favorite, advance them): march.ipynb
     and the manual stepping in predicting26 -> yields a single bracket and one
     champion.
   * PROBABILISTIC MONTE CARLO (sample each game from model probability, repeat
     ~10,000 times, tabulate how far each team advances): march2.ipynb,
     march2.1, march2.11, predicting26 -> yields reach-probabilities per round
     (finishes tables) rather than a single bracket. This is the major
     methodological upgrade across the project.
   * Symmetrization of matchup scoring (average both team orderings) is used in
     the march2 line and predicting26, but not in march.ipynb.

   * 2025: march.ipynb (deterministic) -> champion ARIZONA over Auburn;

7) EVALUATION & VISUALIZATION
   * Metric focus shifts from ACCURACY/.score (march.Rmd AIC; march.ipynb) to
     LOG-LOSS and ROC/AUC with CALIBRATION (march2 line) -- appropriate for
     probabilistic bracket forecasting.
   * Designed figures: march.Rmd = four-factors ggplot suite; march26_scrape =
     bootstrap upset-rate boxplots; march2.ipynb = loss curves, ROC, reliability
     diagram, torchviz NN graph; march2.1 = PCA variance curve, reliability
     diagrams, ROC; march2.11 = plotnine scree plot + per-bin reliability
     scatter. march.ipynb is comparatively figure-light (mostly tables).
   * prediction_results.xlsx adds an outcome-based SCORECARD (bce_loss, Pick,
     Correct, Points, on_path, Upset) for 2026 -- the only place predictions are
     checked against realized results.

8) WEAK SPOTS AND IMPROVEMENTS OVER TIME (technique trajectory)
   * WEAKEST: march.Rmd fits glm() WITHOUT family=binomial on a 0/1 target (a
     linear-probability model, not logistic) and relies on stepwise F-tests with
     no resampling on a tiny (single-season) sample -- high overfit / unstable
     selection risk.
   * march.ipynb selects hyperparameters by scoring candidates directly on the
     TEST set inside nested loops (optimistic/overfit), maintains many nearly
     duplicate tuning cells, and trains a separate small model per round on very
     few examples -- brittle. Repeated near-identical VotingClassifier blocks
     differ mainly in base-estimator hyperparameters (e.g. C/alpha, max_depth,
     n_estimators, max_samples) and which estimators are commented out.
   * CLEAR IMPROVEMENTS in the march2/epilogue line: explicit leakage control;
     difference features + mirrored augmentation; proper CV (RandomizedSearchCV)
     and skorch EarlyStopping/ValidSplit; probability CALIBRATION; principled
     log-loss-optimized ensemble weighting; and Monte Carlo simulation for
     uncertainty. The progression march.ipynb -> march2.ipynb -> march2.1.ipynb
     -> (march2.11 / predicting26) is a steady move from ad-hoc, accuracy-driven,
     single-bracket guessing toward calibrated, cross-validated, simulation-based
     probabilistic forecasting.

9) REPEATED CODE BLOCKS (small differences to note)
   * The difference-feature + mirrored-augmentation block is near-identical in
     "march epilogue training", march2.ipynb, march2.1, march2.11 and
     predicting26; differences are only the stat-name casing (efg_pct/ORtg/DRtg
     vs eFG/off_rtg/def_rtg) and which columns are dropped (march2.1 also drops
     team2/spread/net_rtg).
   * The Bracket class + Monte Carlo loop recurs in march2.ipynb, march2.1,
     march2.11 and predicting26; the main differences are the model set used
     (raw vs PCA; 13-feature saved NN vs in-notebook NN), the number of stored
     bracket CSV shards, and the target year's input files (database25 vs
     database26).
   * The skorch NeuralNetClassifier + RandomizedSearchCV setup is shared by
     march2.1 and march2.11 (same callbacks/criterion/optimizer); march2.1 runs
     it on raw and PCA inputs, march2.11 only on 9-component PCA inputs.
